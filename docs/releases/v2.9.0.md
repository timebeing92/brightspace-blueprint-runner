# Blueprint Wizard v2.9.0

Blueprint Wizard v2.9.0 pairs the local terminal workflow with Blueprint
Bundle v1.4.0. The Wizard's runtime is unchanged from v2.8.1; the release
exists so that the managed launcher, the curl installer and the Workshop Hall
all point at the same verified Runner/Bundle pair.

## What changed in the pair

Bundle v1.4.0 (released 2026-10-13 from `35eb6a55c251fba9cc1b53273920274c89bf6d0c`):

- the structure-fidelity refresh of 2026-10-08: model `coursecraft.blueprint/5`
  (run emphasis, tables, module rows, nested dropdowns, resolved internal
  links), Word headings one to one with the page, panels written between
  bracket lines in the Blueprint Packager's form;
- heading ownership (2026-10-13): a page is parsed once and only then grouped
  into segments, so a panel that opens with a heading stays whole, heading
  inside, with the additive `heading_owner: "panel"` marker on
  `coursecraft.structure/1` segments; a container with no recognised class is
  read from its inline style conservatively; `[box: Label]` keeps the source
  component's name;
- a heading that opens a table cell no longer keeps with the next paragraph,
  which removed the half-empty pages Word and LibreOffice produced (81 pages
  with seven under-filled pages became 76 with none on the MBA 620 August
  export, confirmed in both engines);
- "Page chrome" QA findings are notes, not breaks;
- run receipts are `coursecraft.run/2`, with the run/1 schema shipped beside it.

Runner v2.9.0:

- `scripts/make_release_bundle.py` lists `schemas/run_identity_2_schema.json`
  in the release receipt, so a managed install's health check covers both run
  schemas the Bundle ships;
- both CI jobs check out the Bundle at the released commit;
- the README names the v2.9.0 / v1.4.0 pair.

## Verification boundary

The automated suite is unchanged apart from the receipt test. Release evidence
and exact Runner archive checksums are recorded alongside the published release
rather than predicted in this note. Before publication the pair was verified
with a fresh managed install from the new ZIP, an update of a copy of a real
v2.8.1 managed install with its settings and logs retained, a rollback to
v2.8.1 on that copy, and checksum comparison of every downloaded asset.

The release remains unsigned and is not notarized. Managed installations
verify release metadata and SHA-256 checksums before activating a complete
Runner/Bundle pair; the previous installed version remains available for
rollback.
